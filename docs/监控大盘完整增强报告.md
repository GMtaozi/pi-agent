## 一、完整增强清单

### 1. 时序数据（Time Series）
- `requestTimeSeries` - 请求数趋势
- `durationTimeSeries` - 响应耗时趋势
- `errorTimeSeries` - 错误数趋势
- `memoryTimeSeries` - 内存使用趋势（新增）
- `cpuTimeSeries` - CPU 使用趋势（新增）
- 最大 100 个数据点，自动裁剪

### 2. 告警系统（Alerts）
**内置告警规则**：
| 规则 | 触发条件 | 严重程度 |
|------|----------|----------|
| high-error-rate | 错误率 > 20% | critical |
| slow-response | 平均耗时 > 5000ms | warning |
| high-memory | 内存 > 500MB | warning |
| high-cpu | CPU > 80% | warning（新增） |

### 3. 日志管理（Log Management）
- 结构化日志存储（最多 500 条）
- 按级别过滤（debug/info/warn/error）
- 按服务过滤
- 全文搜索
- 错误堆栈记录

### 4. 健康检查（Health Check）
- 4 个子系统检查：
  - Database
  - Cache
  - Provider
  - Workspace
- 整体状态：healthy / degraded / unhealthy
- 最后检查时间

### 5. 性能分析（Performance Analysis）
- **慢工具**：记录耗时 > 2000ms 的工具调用
- **热点文件**：统计文件访问次数（需要路径追踪支持）
- **P95/P99 延迟**：响应耗时百分位数

### 6. Server 新增端点（共 9 个）
| 端点 | 方法 | 功能 |
|------|------|------|
| /api/monitoring/dashboard | GET | 仪表盘数据 |
| /api/monitoring/metrics | GET | 指标摘要 |
| /api/monitoring/alerts | GET | 告警列表 |
| /api/monitoring/alerts/:id/acknowledge | POST | 确认告警 |
| /api/monitoring/reset | POST | 重置指标 |
| /api/monitoring/health | GET | 健康检查 |
| /api/monitoring/logs | GET | 获取日志（支持过滤） |
| /api/monitoring/logs/search | GET | 搜索日志 |
| /api/monitoring/ws | WS | WebSocket 实时告警 |

### 7. WebSocket 实时推送
- 客户端连接时发送初始仪表盘数据
- 每 5 秒推送未确认告警
- 自动重连与错误处理

### 8. Logger 集成增强
- `Logger` 新增 `onLog` 回调
- Server 初始化时传入 `monitoring.recordLog`
- 所有通过 `Logger` 记录的日志自动进入监控系统

### 9. 系统指标自动收集
- 每 5 秒自动采集：
  - 内存使用（MB）
  - CPU 使用（%）
- 记录到时序数据

### 10. 前端仪表盘（4 个标签页）
**Dashboard**：
- 状态卡片（Status、Uptime、Requests、Success Rate、Avg/P95/P99 Duration、Memory、CPU）
- 5 个时序图表（Request、Duration、Error、Memory、CPU）
- 工具使用统计（含慢调用计数）
- 最近错误列表
- 性能分析（慢工具、热点文件）

**Alerts**：
- 未确认告警列表
- 确认按钮
- 按严重程度着色

**Logs**：
- 日志级别过滤
- 服务过滤
- 全文搜索
- 实时刷新

**Health**：
- 整体健康状态
- 4 个子系统状态
- 运行时间
