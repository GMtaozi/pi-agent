## 2. 模块设计

### 2.1 Agent 引擎（agent-engine）

**职责**：核心 Agent 执行引擎，负责对话循环、工具调用、上下文管理

```typescript
// 核心接口
export interface AgentEngine {
  // 创建会话
  createSession(config: SessionConfig): Promise<Session>;
  
  // 发送消息
  sendMessage(sessionId: string, message: string, options?: SendOptions): Promise<Message>;
  
  // 流式发送
  sendMessageStream(sessionId: string, message: string, onChunk: (chunk: StreamChunk) => void): Promise<void>;
  
  // 停止生成
  stopGeneration(sessionId: string): Promise<void>;
  
  // 获取会话信息
  getSession(sessionId: string): Promise<Session>;
  
  // 获取会话列表
  listSessions(userId: string, options?: ListOptions): Promise<Session[]>;
  
  // 删除会话
  deleteSession(sessionId: string): Promise<void>;
}

// 会话配置
export interface SessionConfig {
  model: string;
  systemPrompt?: string;
  tools?: string[];
  knowledgeBases?: string[];
  temperature?: number;
  maxTokens?: number;
  debug?: DebugConfig;
}

// 调试配置
export interface DebugConfig {
  enabled: boolean;
  breakpoints: Breakpoint[];
  mode: 'normal' | 'step' | 'breakpoint';
}

export interface Breakpoint {
  nodeId: string;
  condition?: string;
  enabled: boolean;
}
```

### 2.2 监控服务（monitoring）

**职责**：执行监控、Token 追踪、成本统计

```typescript
// 核心接口
export interface MonitoringService {
  // 记录执行
  recordExecution(execution: ExecutionRecord): Promise<void>;
  
  // 记录节点执行

export interface ExecutionRecord {
```

## 4. 安全设计

### 4.1 认证与授权

```
┌─────────────────────────────────────────┐
│              认证流程                    │
│                                         │
│  用户登录 → JWT Token → 请求携带        │
│       ↓                                 │
│  Token 验证 → 提取用户身份 → 权限检查   │
│       ↓                                 │
│  通过 → 处理请求                        │
│  失败 → 返回 401                        │
│                                         │
└─────────────────────────────────────────┘
```

### 4.2 数据安全

| 数据类型 | 存储方式 | 加密 |
|----------|----------|------|
| 用户密码 | bcrypt 哈希 | ✅ |
| API Key | AES-256-GCM | ✅ |
| 会话数据 | SQLite | ❌ |
| 知识库文档 | 文件系统 | ❌ |
| 产物文件 | 文件系统 | ❌ |

### 4.3 防护措施

| 威胁 | 防护 |
|------|------|
| SQL 注入 | 参数化查询 |
| XSS | 输入转义、CSP |
| CSRF | Token 验证 |
| 暴力破解 | 限流、账户锁定 |
| 敏感数据泄露 | 加密存储、最小权限 |

## 5. 部署架构

### 5.1 Docker 部署

```yaml
# docker-compose.yml
version: '3.8'

services:
  workforge:
    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DATABASE_URL=/data/workforge.db
      - JWT_SECRET=${JWT_SECRET}
      - OPENAI_API_KEY=${OPENAI_API_KEY}
    volumes:
      - ./data:/data
      - ./workspace:/workspace
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    restart: unless-stopped

volumes:
  redis-data:
```

### 5.2 性能优化

| 方面 | 措施 |
|------|------|
| 数据库 | 索引优化、连接池、WAL 模式 |
| 缓存 | Redis 缓存热点数据 |
| 流式 | SSE 流式输出，减少等待 |
| 前端 | 懒加载、代码分割、虚拟滚动 |
| 文件 | 分片上传、断点续传 |
