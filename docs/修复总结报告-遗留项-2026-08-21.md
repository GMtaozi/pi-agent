## 二、Markdown 渲染修复详情

### 问题
- 前端直接渲染用户输入，存在 🔴 高危 XSS 漏洞
- WorkspacePage 无 Markdown 支持
- 代码高亮缺失

### 修复内容

#### 后端（apps/server/src/index.ts）
- 引入 `marked` + `sanitize-html`
- 重写 `markdownToHtml()`：
  - 先用 `marked.parse()` 生成 HTML
  - 再用 `sanitize-html` 白名单清洗
  - 允许标签：`h1-h6`, `p`, `br`, `hr`, `strong`, `em`, `del`, `ins`, `ul`, `ol`, `li`, `blockquote`, `pre`, `code`, `table`, `thead`, `tbody`, `tr`, `th`, `td`, `a`, `img`, `div`, `span`, `sup`, `sub`
  - 允许属性：`href`, `title`, `target`, `rel`, `src`, `alt`, `class`
  - 允许协议：`http`, `https`, `mailto`
  - `a` 标签强制加 `target="_blank" rel="noopener noreferrer"`

#### 前端（apps/web/src/components/MarkdownRenderer.tsx）
- 创建统一 `MarkdownRenderer` 组件
- 使用 `react-markdown` + `remark-gfm` + `rehype-sanitize`
- `rehype-sanitize` 基于扩展后的 `defaultSchema` 清洗 HTML
- 保留 `code`/`pre` 的 `class` 属性以支持语法高亮
- `react-markdown` 本身不渲染原始 HTML，形成第一层防护
- `rehype-sanitize` 形成第二层防护

#### 代码高亮
- 使用 `react-syntax-highlighter` (Prism + vscDarkPlus 主题)
- 自动检测语言并高亮

#### WorkspacePage 集成
- `.md` 文件已接入统一 `MarkdownRenderer`
- 后端 preview 端点返回的 HTML 也经过 `sanitize-html` 清洗

### 验证结果
- 前端测试 9/9 通过
- 后端测试 99/99 通过
- `vite build` 成功
- 无功能回归

## 四、安全修复总结

### XSS 防护措施

| 层级 | 措施 | 位置 |
|------|------|------|
| 后端 | `marked.parse()` + `sanitize-html` 白名单 | `apps/server/src/index.ts` |
| 前端 | `react-markdown` 不渲染原始 HTML | `apps/web/src/components/MarkdownRenderer.tsx` |
| 前端 | `rehype-sanitize` 白名单清洗 | `apps/web/src/components/MarkdownRenderer.tsx` |

### 白名单策略

**允许的标签：**
- 标题：`h1`-`h6`
- 文本：`p`, `br`, `hr`, `strong`, `em`, `del`, `ins`
- 列表：`ul`, `ol`, `li`
- 引用：`blockquote`
- 代码：`pre`, `code`
- 表格：`table`, `thead`, `tbody`, `tr`, `th`, `td`
- 链接/图片：`a`, `img`
- 容器：`div`, `span`, `sup`, `sub`

**允许的属性：**
- `a`: `href`, `title`, `target`, `rel`
- `img`: `src`, `alt`, `title`
- `code`, `pre`, `span`, `div`: `class`（语法高亮需要）

**允许的协议：**
- `http`, `https`, `mailto`
