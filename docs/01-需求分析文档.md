## 1. 文档目的与范围

本文档定义一款"个人 AI 内容工厂"产品的业务需求、功能需求、非功能需求与验收标准。产品形态参考已调研的竞品（Pi-mato、Codex、Claude、ChatGPT 等），核心理念来自"AI 时代组织演进"框架：一个用户 = 一个超级个体/微型公司，通过对话驱动，产出软件、文档、图片、视频等任意介质交付物。

本文档面向：产品经理、研发团队、设计团队、测试团队。

---

## 2. 背景与动机

### 2.1 行业背景

- 多模态大模型（文本、图片、视频、语音）能力快速成熟，单一模型即可理解并生成多种介质（如 MiniMax H3、GPT-5.x、DeepSeek 系列）。
- 现有编码助手（Codex、Claude Code）聚焦代码单一产物；现有聊天工具（ChatGPT）产出不可管理、不可迭代的对话文本。
- 缺少"一个入口、任意交付物、可管理、可迭代"的个人内容生产工具。

### 2.2 机会窗口

| 用户痛点 | 现状 | 本产品机会 |
|---|---|---|
| 想做 PPT/落地页/视频，但不会用专业工具 | 逐个工具学，成本高 | 对话一句描述即产出 |
| 生成的内容不可管理、不可迭代 | 聊天记录即一切 | 工作台统一管理全部产物 |
| 每次都要重新交代背景 | 无记忆 | 跨会话记忆自动带入 |
| 生成质量不可控 | 一次性生成 | 对话式修订闭环 |

### 2.3 产品愿景

> 让任何一个人，用一句自然语言，得到一份可管理、可迭代、可交付的专业产物。

## 3. 产品定位

### 3.1 一句话定位

个人 AI 软件生态工作台：以对话为入口、以 Agent 为执行引擎、以文件工作台为产物仓库，以软件/应用/网页等代码类产物为主要交付物，兼顾文档、图片、视频等内容产物；以记忆为状态、以 Skills 为能力插件的"一人公司"操作系统。

### 3.2 核心价值主张

1. 对话即生产：不需要学工具，描述需求即可。
2. 软件生态优先（2026-08-17 战略确认）：主要产出软件/应用/网页等代码类产物，文档、图片、视频等内容产物作为辅助能力逐步补齐。
3. 产物即资产：所有产出物进入工作台，可查看、运行、下载、继续迭代。
4. 能力即插件：代码/文本/图片/视频/语音能力按需挂载（Capability Cloud）。
5. 记忆即上下文：跨会话记住偏好与历史产物，越用越懂用户。

### 3.3 目标用户

| 用户画像 | 特征 | 典型场景 |
|---|---|---|
| 独立开发者/小团队（首要用户） | 一人多能，需要软件/原型快速落地 | 一句话 → 可运行的落地页/小工具/Web 应用 |
| 内容创作者 | 需要多介质产出，效率优先 | 一条口播稿 → 音频 → 视频 |
| 职场人 | 需要汇报材料 | 一个主题 → PPT/一页纸 |
| 学生/自媒体 | 低成本试错 | 想法 → 原型/图文草稿 |

### 3.4 非目标（MVP 明确不做）

- 不做多用户协作/企业版（后续阶段）。
- 不做本地模型训练/微调。
- 不做复杂的财务/权限体系。
- 不做 App 端（MVP 仅 Web）。

## 4. 竞品分析

| 竞品 | 优点 | 缺点 | 对我们的启示 |
|---|---|---|---|
| Pi-mato（截图参考） | 工作台+记忆+Skills 三件套完整；多模态演示闭环 | 功能面宽、深度待验证 | 验证了"工作台产物管理"的价值 |
| Codex / Claude Code | Agent 执行能力极强、工具链成熟 | 仅代码产物；无面向普通用户的工作台 | Agent 引擎可复用其思路/开源实现 |
| ChatGPT / Gemini | 对话体验好、多模态输入 | 产物不可管理；迭代靠复制粘贴 | 必须有产物仓库 |
| 即梦 / 可灵等 | 单点生成质量高 | 单一介质；无编排 | 生成能力应作为"能力插件"接入 |

差异化结论：不做"更强的生成"，做"统一的产物编排与管理"。生成模型会趋同，编排层（工作台+记忆+Skills+修订闭环）才是壁垒。

### 5.1 术语表

| 术语 | 定义 |
|---|---|
| 对话（Chat） | 用户与 Agent 的交互会话 |
| 工作台（Workspace） | 产物文件的统一管理空间（项目目录） |
| 产物（Artifact） | 工作台中的一个交付文件（html/md/mp4/图片等） |
| Skills | 可插拔的能力包：工具 + 提示词 + 元数据 |
| 记忆（Memory） | 跨会话持久化的用户偏好与产物摘要 |
| 任务计划（Schedule） | 定时/周期触发的自动化任务 |
| 修订闭环（Iterate） | 生成 → 反馈 → 修改的循环 |

## 6. 功能需求

### 6.1 功能模块总览

| 模块 | 优先级 | 阶段 |
|---|---|---|
| M1 对话与 Agent 引擎 | P0 | Phase 0 |
| M2 工作台（产物管理） | P0 | Phase 0 |
| M3 修订闭环 | P0 | Phase 0 |
| M4 能力插件层（Capability Cloud） | P0 | Phase 0（文本）→ Phase 1（多模态） |
| M5 记忆系统 | P1 | Phase 2 |
| M6 任务计划 | P1 | Phase 2 |
| M7 治理与审批 | P1 | Phase 2 |
| M8 用户与设置 | P2 | Phase 0 基础版 |

### 6.2 M1 对话与 Agent 引擎（P0）

需求描述：用户以自然语言对话，Agent 自主规划、调用工具、产出文件。

功能点：

| ID | 需求 | 优先级 |
|---|---|---|
| M1-1 | 支持多模型接入（OpenAI、DeepSeek、MiniMax、Anthropic、Google 等），可切换 | P0 |
| M1-2 | 支持多轮对话、流式输出 | P0 |
| M1-3 | Agent 可自主调用工具（读写文件、执行命令、生成媒体） | P0 |
| M1-4 | 支持上下文加载（AGENTS.md/项目说明自动加载） | P1 |
| M1-5 | 支持会话历史查看、重命名、删除、继续 | P1 |
| M1-6 | 支持图片输入（截图/粘贴） | P1 |

验收标准：
- 用户输入"生成一个 hello world 网页"，30 秒内工作台出现可预览的 HTML 文件。
- 切换模型后，新对话使用新模型，历史不受影响。

### 6.3 M2 工作台（产物管理）（P0）

需求描述：工作台是全部产物的统一管理空间。

功能点：

| ID | 需求 | 优先级 |
|---|---|---|
| M2-1 | 文件树展示工作台目录结构，按类型图标区分 | P0 |
| M2-2 | 支持预览：HTML 内嵌渲染、图片、视频、音频、Markdown、代码 | P0 |
| M2-3 | 支持产物下载 | P0 |
| M2-4 | 支持产物重命名、删除、新建 | P1 |
| M2-5 | 支持产物编辑并让 Agent 继续迭代 | P1 |
| M2-6 | 支持产物版本/快照（修订前可回退） | P2 |
| M2-7 | 支持多工作台切换 | P1 |

验收标准：
- 生成的 5.html 自动出现在文件树中，点击可预览。
- 删除产物有二次确认。

### 6.4 M3 修订闭环（P0）

需求描述：生成物不是一次性的，用户反馈后 Agent 原地修订。

功能点：

| ID | 需求 | 优先级 |
|---|---|---|
| M3-1 | 对话中引用具体产物（"把 5.html 标题改大"）时，Agent 自动定位并修改 | P0 |
| M3-2 | 修改后工作台立即刷新，保留修改记录 | P1 |
| M3-3 | 支持撤销到上一版 | P2 |

验收标准：
- 连续 3 轮"改一下 → 再改一下"的指令，产物每次正确更新且不丢失。

### 6.5 M4 能力插件层（Capability Cloud）（P0→P1）

需求描述：文本、图片、视频、语音等生成能力以"技能/工具"形式按需挂载，模型差异对上层透明。

MVP（Phase 0）能力：

| 能力 | 说明 | 优先级 |
|---|---|---|
| 软件/应用生成 | Agent 核心能力：落地页、小工具、Web 应用（写文件 + 本地运行/预览） | P0 |
| HTML/PPT 生成 | 文档类产物（reveal.js 风格 PPT、落地页） | P0 |
| Markdown 文档 | 方案、口播稿、笔记 | P0 |

Phase 1 追加能力：

| 能力 | 接入方式 | 优先级 |
|---|---|---|
| 图片生成 | 图像 API（Flux/Step/即梦等）封装为工具 | P1 |
| 语音合成 | TTS 工具（如 edge-tts / 商业 TTS） | P1 |
| 视频生成/组装 | 视频 API（如 MiniMax H3）+ 程序化拼接 | P1 |
| 音频转写 | ASR 工具 | P2 |

Skills 元数据结构：

````yaml
name: html-ppt
description: 生成 reveal-style HTML 演示文稿
triggers: [PPT, 幻灯片, slides, 演示]
tools: [write, generate_image]
prompt: |
  <技能提示词模板>
````

验收标准：
- Skills 面板可列出全部已装技能，开关即时生效（热加载）。
- 新增一个技能只需放置一个文件，无需重启。

### 6.6 M5 记忆系统（P1）

需求描述：跨会话记住用户偏好与产物摘要。

功能点：

| ID | 需求 | 优先级 |
|---|---|---|
| M5-1 | 会话结束时自动沉淀"偏好 + 产物摘要"到记忆库 | P1 |
| M5-2 | 新会话自动注入相关记忆 | P1 |
| M5-3 | 记忆可视化：用户可查看/删除/关闭记忆条目 | P1 |
| M5-4 | 记忆支持手动写入（用户主动让 Agent 记住某事） | P2 |

验收标准：
- 用户设置"我喜欢深色风格"后，新会话生成页面默认深色。

### 6.7 M6 任务计划（P1）

需求描述：定时/周期自动执行任务（如每 10 分钟生成编号递增的 hello world）。

功能点：

| ID | 需求 | 优先级 |
|---|---|---|
| M6-1 | 创建定时任务（cron 表达式 + 任务描述） | P1 |
| M6-2 | 任务执行结果通知（对话中/系统通知） | P1 |
| M6-3 | 任务列表管理（启用/暂停/删除/查看历史） | P1 |
| M6-4 | 任务幂等：重复执行不产生脏数据 | P1 |

验收标准：
- 定时任务按计划触发，产物编号连续递增且无重复。

### 6.8 M7 治理与审批（P1）

需求描述：对高影响操作（删除、覆盖、执行命令、付费调用）进行分级控制。

功能点：

| ID | 需求 | 优先级 |
|---|---|---|
| M7-1 | 分级策略：Do（自动）/ Review（记录+通知）/ Approve（确认）/ Deny | P1 |
| M7-2 | 高危操作（删除文件、覆盖产物、大额 API 调用）默认 Approve | P1 |
| M7-3 | 审批弹窗在对话界面内联完成 | P1 |
| M7-4 | 审计日志：记录所有 Agent 对工作台的操作 | P1 |

验收标准：
- 触发删除时弹出确认，取消后文件未被删除。
- 审计日志可追溯任意产物的修改历史。

### 6.9 M8 用户与设置（P2）

| ID | 需求 | 优先级 |
|---|---|---|
| M8-1 | 本地用户：无需注册，首次启动即用 | P0 |
| M8-2 | 模型供应商 API Key 配置（界面录入，本地存储） | P0 |
| M8-3 | 工作台目录选择 | P1 |
| M8-4 | 界面主题（亮/暗） | P2 |

## 7. 非功能需求

### 7.1 性能

| 指标 | 目标 |
|---|---|
| 首屏加载 | < 2s |
| 对话首 token 延迟 | < 3s（受模型影响） |
| 产物预览（HTML/图片） | < 1s |
| 并发对话 | 单用户 >= 3 个并行会话 |

### 7.2 安全与隐私

- API Key 本地加密存储，绝不落库明文、绝不随前端下发。
- 工作台默认仅本地访问；如需公网，需显式授权。
- 所有产物默认私有。
- 提供"清除全部数据"功能。

### 7.3 成本

- 模型调用成本预估展示（每次对话显示 token/费用估算）。
- 支持设置月度预算上限，超限自动暂停高成本操作（P2）。

### 7.4 可扩展性

- 能力插件层开放 SDK：第三方可发布 Skills。
- Agent 引擎可替换（协议层抽象）。

### 7.5 兼容性

- 浏览器：Chrome/Edge 最新两个大版本。
- 桌面端：Electron/Tauri 打包（P2，MVP 仅 Web）。

## 8. 用户故事（示例）

1. 做软件：作为独立开发者，我想说"做一个番茄钟小工具"，以便直接拿到可运行的 Web 应用。
2. 做落地页：作为小团队，我想说"给新产品做个落地页"，以便快速上线验证。
3. 迭代：作为开发者，我想说"5.html 改成浅色主题"，以便产物符合品牌规范。
4. 记忆：作为用户，我想让系统记住"我常用粤语"，以便每次生成都默认粤语。
5. 定时：作为开发者，我想让系统"每 10 分钟生成编号递增的 hello world"，以便测试流水线。
6. 做内容（辅助）：作为内容运营，我想说一句"把这段口播稿做成 PPT"，以便 5 分钟内拿到可演讲的文稿。

## 9. 里程碑规划

| 阶段 | 目标 | 周期 | 交付物 |
|---|---|---|---|
| Phase 0 | 软件生态闭环 MVP | 2-4 周 | 对话 + 工作台 + 修订闭环 + 软件/网页产物 |
| Phase 1 | 多模态能力 | +2-4 周 | 图片/视频/语音工具接入，统一产物管理 |
| Phase 2 | 记忆 + 任务 + 治理 | +2-4 周 | 记忆系统、定时任务、分级审批、审计 |
| Phase 3 | 打磨与发布 | 持续 | 性能、稳定性、Skills 生态、桌面端 |

Phase 0 退出标准（Go/No-Go）：
- [ ] 用户可对话生成软件/网页（HTML/落地页/小工具）并在工作台预览、运行、下载。
- [ ] 连续 3 轮修订指令产物正确更新。
- [ ] 切换模型不丢会话。
- [ ] API Key 配置流程安全可用。

## 10. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 模型能力趋同，无壁垒 | 高 | 聚焦编排层（工作台/记忆/Skills/闭环） |
| 功能面过宽，每个都浅 | 高 | 严格按 Phase 推进，MVP 砍掉多模态 |
| 生成质量不稳定 | 中 | 修订闭环 + 提示词模板（Skills）收敛质量 |
| 成本失控 | 中 | 费用展示 + 预算上限 |
| 隐私泄露 | 高 | 本地优先存储、密钥加密、最小权限 |
| 视频生成慢/贵 | 中 | 走"组装"路线：片段生成 + 程序拼接，预留降级 |
