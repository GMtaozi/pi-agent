## 三、Markdown 渲染审查

### 3.1 前端实现 (`ChatPage.tsx`)

**实现位置**：`apps/web/src/pages/ChatPage.tsx:394-450`

**功能**：
- `renderInlineMarkdown`：支持粗体 `**text**`、行内代码 `` `text` ``、斜体 `*text*`
- `renderMarkdown`：基于代码块分割，支持 ` ``` ` 代码块

**依赖**：无（自实现）

### 3.2 后端实现 (`apps/server/src/index.ts`)

**实现位置**：`apps/server/src/index.ts:29-49`

**功能**：
- 支持 h1-h6、粗体、斜体、行内代码、代码块
- 基础 XSS 防护：转义 `&`, `<`, `>`
- 在 `/api/workspaces/:id/preview` 中对 `.md`/`.markdown` 文件进行 HTML 转换

### 3.3 审查意见

#### 安全性

| 问题 | 严重性 | 位置 | 说明 |
|------|--------|------|------|
| XSS 漏洞 | 🔴 高 | 前端 `renderMarkdown` | 直接将用户输入渲染为 JSX，无转义处理 |
| 后端防护不完整 | 🟡 中 | 后端 `markdownToHtml` | 转义顺序正确，但代码块内容已被转义可能导致显示异常 |

#### 功能完整性

| 问题 | 严重性 | 说明 |
|------|--------|------|
| 语法支持有限 | 🟡 中 | 不支持链接、图片、列表、表格、任务列表等常见语法 |
| 无语法高亮 | 🟢 低 | 代码块无语言高亮 |
| 前后端不一致 | 🟡 中 | 后端支持标题，前端不支持 |

#### 性能

| 问题 | 严重性 | 说明 |
|------|--------|------|
| 无记忆化 | 🟡 中 | 每次渲染都重新执行 `split` 和正则，长消息性能差 |
| 全局正则 | 🟢 低 | `renderInlineMarkdown` 使用全局正则，多次调用可能有效率问题 |

#### 代码质量

| 问题 | 严重性 | 说明 |
|------|--------|------|
| 缺少类型注解 | 🟢 低 | `renderMarkdown` 返回 `JSX.Element[]` 但未显式标注 |
| 无错误处理 | 🟡 中 | 输入为 `null`/`undefined` 时会抛出异常 |
| 无单元测试 | 🟡 中 | 测试文件未覆盖 Markdown 渲染逻辑 |
| 多余段落 | 🟢 低 | 每行都被 `<p>` 包裹，可能导致多余间距 |

### 3.4 建议

| 优先级 | 建议 |
|--------|------|
| P0 | 前端添加 XSS 防护：对用户输入进行转义或使用 DOMPurify |
| P0 | 添加单元测试覆盖 `renderMarkdown` 和 `renderInlineMarkdown` |
| P1 | 考虑引入 `react-markdown` 或 `marked` 替代自实现 |
| P1 | 统一前后端 Markdown 渲染能力 |
| P2 | 添加记忆化优化长消息渲染性能 |
| P2 | 支持更多 Markdown 语法（链接、列表等） |
