## 一、项目定位与核心价值

**一句话定位**：个人 AI 软件生态工作台 —— 以对话为入口、以 Agent 为执行引擎、以文件工作台为产物仓库，以软件/应用/网页等代码类产物为主要交付物，兼顾文档、图片、视频等内容产物；以记忆为状态、以 Skills 为能力插件的"一人公司"操作系统。

**核心价值**：
1. 对话即生产：不需要学工具，描述需求即可。
2. 软件生态优先：主要产出软件/应用/网页等代码类产物，文档、图片、视频等内容产物作为辅助能力逐步补齐。
3. 产物即资产：所有产出物进入工作台，可查看、运行、下载、继续迭代。
4. 能力即插件：代码/文本/图片/视频/语音能力按需挂载。
5. 记忆即上下文：跨会话记住偏好与历史产物，越用越懂用户。

**差异化壁垒**：不做"更强的生成"，做"统一的产物编排与管理"。生成模型会趋同，编排层（工作台 + 记忆 + Skills + 修订闭环）才是壁垒。

+-------------------------------------+---------------------------------+
                                      |
+-------------------------------------v---------------------------------+

|  AgentSession（对话循环/工具调用/上下文/流式）                          |

+-------------------------------------+---------------------------------+
                                      |
+------------------+-------------------+------------------+-------------+
|                  |                   |                  |             |
+----v-------------+----v--------------+----v-------------+----v--------+
| 模型适配层        | 多模态工具层       | 存储层           | 系统工具     |

### 2.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| Agent 引擎 | @earendil-works/pi-coding-agent（SDK：AgentSession） | 成熟的多模型 Agent 循环、工具调用、会话、流式；本地源码可改 |
| 后端运行时 | Node.js 22+ | 与 Pi SDK 同栈，生态成熟 |
| 前端 | React + Vite | 生态成熟，快速迭代 UI |
| 实时通信 | SSE（流式）+ WebSocket（工作台刷新/通知） | 简单可靠 |
| 元数据存储 | SQLite | 单机零运维，结构化查询 |
| 产物存储 | 文件系统（工作台目录） | 产物即文件，可直接用系统工具打开 |
| 记忆存储 | JSON 索引（Phase 2 可升级向量库） | 初期简单，可检索 |
| 任务调度 | node-cron | 轻量定时 |
| 密钥存储 | AES-256-GCM 加密文件 | 不落库明文 |

## 五、三阶段演进路线

### Phase 0：软件生态闭环 MVP（2-4 周）

**目标**：验证主链路 —— 对话 → 生成软件/网页 → 工作台预览 → 修订闭环。

**交付物**：
- 对话面板（多模型切换、流式输出）
- 工作台（文件树、预览、下载）
- 修订闭环（引用产物、原地修改）
- 基础能力：软件/网页生成、HTML/PPT、Markdown
- 设置（API Key 本地加密存储）

**Go/No-Go 标准**：
- [ ] 用户可对话生成软件/网页并在工作台预览、运行、下载。
- [ ] 连续 3 轮修订指令产物正确更新。
- [ ] 切换模型不丢会话。
- [ ] API Key 配置流程安全可用。

### Phase 1：多模态能力（+2-4 周）

**目标**：补齐图片/视频/语音能力，统一产物管理。

**交付物**：
- 图片生成（接 1 家图像 API）
- 语音合成（TTS）
- 视频组装管线（脚本-分镜-片段-ffmpeg 拼接），接 MiniMax H3 一家打通链路
- 音频转写（ASR）
- Skills 面板与热加载

**关键决策**：
- 视频第一阶段不含口播/字幕对齐。
- 其余视频 API 走统一适配接口预留。

### Phase 2：记忆 + 任务 + 治理（+2-4 周）

**目标**：让产品"越用越懂用户"，并具备自动化与安全治理能力。

**交付物**：
- 记忆系统（JSON + 标签起步，支持跨会话注入）
- 任务调度（cron 定时任务）
- 治理与审批（分级策略、审批弹窗、审计日志）
- 多工作台切换
- 产物版本快照

**后续**：
- Phase 2 末尾评估是否升级 Tauri 桌面壳。
- Phase 2 视用户量决定是否开放 npm/git Skills 安装。

## 七、核心流程设计（Phase 0 主链路）

### 7.1 对话生成产物

```
用户输入 "生成 hello world 网页"
  -> ChatService.prompt() -> AgentSession.prompt()
  -> Agent 规划 -> 调用 write 工具写 workspace/5.html
  -> 文件监听触发 -> WebSocket 推前端 -> 文件树出现 5.html
  -> Agent 完成 -> SSE 流式回复结束
  -> 用户点预览 -> 沙箱 iframe 渲染
```

### 7.2 修订闭环

```
用户输入 "把 5.html 标题改大"
  -> Agent 解析引用（会话上下文含文件树/内容）
  -> （可选）治理 Review：工作台内修改默认放行
  -> Agent 调用 edit 工具原地修改 5.html
  -> 工作台刷新 + 版本快照（P2）
  -> Agent 回复修改摘要
```

## 八、数据模型要点

### 8.1 SQLite 表（核心）

- workspaces：工作台元数据
- sessions：会话元数据（关联工作台、模型、JSONL 会话文件）
- schedules：定时任务（cron、prompt、状态）
- audit_log：审计日志（工具调用、审批记录）

### 8.2 记忆文件（JSON）

- 按工作台组织，条目含 id、text、tags、ts。
- Phase 2 可升级 FTS5 或向量检索。

### 8.3 产物即文件约定

- 工作台目录即产物仓库，文件名 = 产物名。
- 元数据放同目录 .workforge/artifacts.json（可选）。
- 版本快照放 .workforge/versions/<file>/<ts>-<file>。

## 九、非功能要求

| 维度 | 目标 |
|---|---|
| 首屏加载 | < 2s |
| 对话首 token 延迟 | < 3s（受模型影响） |
| 产物预览 | < 1s |
| 并发对话 | 单用户 >= 3 个并行会话 |
| 安全 | API Key 本地加密、产物默认私有、提供清除全部数据 |
| 成本 | 每次对话显示 token/费用估算，支持预算上限（P2） |
| 兼容性 | Chrome/Edge 最新两个大版本；Phase 2 末支持 Tauri 桌面壳 |

## 十、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 模型能力趋同，无壁垒 | 高 | 聚焦编排层（工作台/记忆/Skills/闭环） |
| 功能面过宽，每个都浅 | 高 | 严格按 Phase 推进，MVP 砍掉多模态 |
| 生成质量不稳定 | 中 | 修订闭环 + 提示词模板（Skills）收敛质量 |
| 成本失控 | 中 | 费用展示 + 预算上限 |
| 隐私泄露 | 高 | 本地优先存储、密钥加密、最小权限 |
| 视频生成慢/贵 | 中 | 走"组装"路线：片段生成 + 程序拼接，预留降级 |

## 十一、下一步行动建议

1. **环境准备**：初始化 monorepo（apps/web + apps/server + packages/*），配置 Node.js 22+ 与 pnpm/npm。
2. **Phase 0 垂直切片**：先做一个最小可运行 demo：
   - 后端：Node 服务 + Pi SDK 接入 + 会话管理 + 文件读写工具注册。
   - 前端：React 对话面板 + 工作台文件树 + HTML 沙箱预览。
   - 验证：用户输入"生成 hello world 网页" → 30 秒内工作台出现可预览 HTML。
3. **基础设施**：SQLite 元数据存储、API Key 加密存储、SSE 流式通信、文件监听刷新。
4. **持续迭代**：demo 跑通后按模块优先级依次补齐 M2-M4、M8，进入完整 Phase 0。

## 十二、核心原则（一句话总结）

> **软件生态优先、编排层为壁垒、Phase 0 做深主链路、多模态按 Phase 渐进、本地优先、安全兜底。**
