## 1. 设计目标与原则

### 1.1 目标

- 以 Agent 为执行引擎，把"想法 → 交付物"的链路压缩到一个界面。
- 全部产物进入统一工作台，可管理、可迭代。
- 能力（文本/图片/视频/语音）以插件形式按需挂载，模型差异对上层透明。
- 单机优先：本地存储、本地密钥、最小运维，可平滑演进到多人版。

### 1.2 设计原则

1. 复用优先：Agent 循环、工具调用、会话管理复用成熟开源实现（Pi SDK），不重造轮子。
2. 产物即文件：所有交付物都是普通文件，工作台即目录，无私有二进制格式。
3. 能力即工具：每个生成模型 = 一个 Agent 工具，注册即用。
4. 编排分层：对话层 → 引擎层 → 工具层 → 存储层，各层接口化。
5. 渐进式：Phase 0 只做文本/HTML 闭环，多模态作为工具增量接入。

## 3. 模块设计

### 3.1 会话服务（Chat/Session）

职责：管理对话生命周期、消息历史、模型切换。

- 复用 Pi SDK 的 AgentSession + SessionManager（JSONL 会话文件）。
- 每个前端对话 = 一个 AgentSession，SSE 转发消息事件。
- 模型切换：Session.setModel()，热切换。
- 会话元数据（名称/时间/关联工作台）存 SQLite。

关键接口：

````typescript
interface ChatService {
  createSession(workspaceId: string, model: string): Promise<string>;
  prompt(sessionId: string, text: string, images?: ImageContent[]): void; // 流式经 SSE
  steer(sessionId: string, text: string): void;
  abort(sessionId: string): Promise<void>;
  switchModel(sessionId: string, model: string): Promise<void>;
  listSessions(workspaceId: string): SessionMeta[];
}
````

### 3.2 工作台服务（Workspace/Artifact）

职责：产物（文件）的 CRUD、预览、索引。

- 工作台 = 一个物理目录（如 ~/workforge/workspaces/<name>/）。
- 文件树：扫描目录生成（忽略 .git/node_modules 等）。
- 预览：HTML 走沙箱 iframe（禁脚本外联）；软件/网页产物支持本地运行预览（Node/静态服务）；图片/视频/音频走静态服务；Markdown 前端渲染。
- Agent 写文件后通过文件监听（chokidar）推送 WebSocket 刷新。
- 版本快照（P2）：写前复制到 .versions/。

### 3.3 能力插件层（Capability Cloud）

职责：统一注册与发现"能力工具"。

````typescript
interface Capability {
  name: string;            // generate_image
  label: string;
  description: string;
  category: "code" | "text" | "image" | "video" | "audio" | "system";  // code 类优先（软件生态战略）
  cost: "free" | "api" | "expensive";
  execute(params: unknown, ctx: ToolContext): Promise<ArtifactRef>;
}
````

Skills 包 = 目录（SKILL.md + 工具实现 + 提示词）。加载器扫描 ~/.workforge/skills 与工作台 .workforge/skills，支持热重载。

战略确认（2026-08-17）：以软件生态为主要目标，代码/软件类能力优先；内容类能力（图片/视频/语音）作为辅助按序补充。

Phase 1 能力实现要点：
- generate_image：调图像 API，产物写工作台，返回文件路径。
- generate_video：走"组装"路线：脚本/分镜 → 片段 API → ffmpeg 拼接 → 产物；第一阶段不含口播/字幕对齐。
- generate_audio：TTS 生成 + 可选多轨合成。

### 3.4 记忆服务（Memory）

职责：跨会话持久化偏好与产物摘要。

- 存储：JSON 文件 + 关键词索引（Phase 2 可换向量库）。
- 写入：会话结束钩子（agent_settled）自动沉淀；用户显式"记住…"亦写入。
- 注入：新会话 system prompt 注入相关记忆（按关键词/工作台匹配）。
- 隐私：记忆条目可单独查看/删除/关闭。

### 3.5 任务调度（Schedule）

职责：定时/周期任务执行。

- 存储：SQLite 任务表（cron、prompt、workspace、状态、lastRun、nextRun）。
- 触发：node-cron 调度，命中后新建"无人值守会话"执行 prompt，结果回写对话记录 + 通知。
- 幂等：任务内产物编号基于目录扫描（如生成下一个 N.html），天然不重复。

### 3.6 治理服务（Policy/Approve/Audit）

职责：高危操作分级控制与审计。

- 四级策略：Do / Review / Approve / Deny，按"工具+参数模式"配置（默认表见下）。

| 操作 | 默认策略 |
|---|---|
| read/grep/find/ls | Do |
| write/edit（工作台内） | Do |
| write/edit（工作台外/覆盖产物） | Review |
| delete/rm | Approve |
| bash 命令 | Review（白名单 Do） |
| 付费 API 调用（图片/视频） | Approve（超预算时） |

- 审批流：Agent 工具执行前挂起，前端弹窗 → 用户确认/拒绝 → 放行或拒绝回传 Agent。
- 审计：所有工具调用写 append-only 日志（时间/工具/参数摘要/结果/审批人）。

### 3.7 设置与密钥

- API Key：界面录入 → AES-256-GCM 加密存本地 → 运行时注入模型适配层。
- 前端永不见明文 Key。

## 4. 数据模型

### 4.1 SQLite 表

````sql
-- 工作台
CREATE TABLE workspaces (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  path TEXT NOT NULL UNIQUE,
  created_at INTEGER NOT NULL
);

-- 会话
CREATE TABLE sessions (
  id TEXT PRIMARY KEY,
  workspace_id TEXT REFERENCES workspaces(id),
  title TEXT,
  model TEXT,
  session_file TEXT,           -- JSONL 路径
  created_at INTEGER NOT NULL
);

-- 任务计划
CREATE TABLE schedules (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL,
  cron TEXT NOT NULL,
  prompt TEXT NOT NULL,
  enabled INTEGER DEFAULT 1,
  last_run_at INTEGER,
  next_run_at INTEGER
);

-- 审计日志
CREATE TABLE audit_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts INTEGER NOT NULL,
  session_id TEXT,
  tool TEXT NOT NULL,
  args_summary TEXT,
  result_summary TEXT,
  policy TEXT NOT NULL,          -- do/review/approve/deny
  decision TEXT                  -- allowed/denied/approved
);
````

### 4.2 记忆文件（JSON）

````json
{
  "workspace": "minimax-h3",
  "entries": [
    { "id": "m1", "text": "用户偏好深色主题", "tags": ["preference"], "ts": 1755400000000 }
  ]
}
````

### 4.3 产物即文件约定

- 工作台目录即产物仓库，文件名 = 产物名。
- 元数据（作者会话、生成时间、版本）放同目录 .workforge/artifacts.json（可选）。
- 版本快照放 .workforge/versions/<file>/<ts>-<file>。

## 5. 关键流程设计

### 5.1 对话生成产物（主链路）

````
用户输入 "生成 hello world 网页"
  -> ChatService.prompt() -> AgentSession.prompt()
  -> Agent 规划 -> 调用 write 工具写 workspace/5.html
  -> 文件监听触发 -> WebSocket 推前端 -> 文件树出现 5.html
  -> Agent 完成 -> SSE 流式回复结束
  -> 用户点预览 -> 沙箱 iframe 渲染
````

### 5.2 修订闭环

````
用户输入 "把 5.html 标题改大"
  -> Agent 解析引用（会话上下文含文件树/内容）
  -> （可选）治理 Review：工作台内修改默认放行
  -> Agent 调用 edit 工具原地修改 5.html
  -> 工作台刷新 + 版本快照（P2）
  -> Agent 回复修改摘要
````

### 5.3 定时任务

````
cron "*/10 * * * *" 触发
  -> ScheduleService 取任务 -> 创建无人值守会话
  -> prompt("扫描目录，生成下一个编号的 hello world HTML，写文件，提交摘要")
  -> 结果落 audit + 对话记录 -> 前端通知
````

### 5.4 审批流程

````
Agent 请求删除产物
  -> PolicyService 判定 Approve
  -> 工具挂起 -> 前端弹窗（显示操作详情）
  -> 用户批准 -> 放行执行 -> 审计记录
  -> 用户拒绝 -> 拒绝回传 Agent -> Agent 调整方案
````

## 8. 非功能设计

### 8.1 安全

- HTML 预览沙箱：iframe sandbox 属性，禁同源、禁脚本执行（或 CSP 严格）。
- bash 工具默认禁用，需在设置中显式开启 + 策略控制。
- 密钥加密存储（AES-256-GCM）。
- 所有对外接口本机绑定（127.0.0.1），公网需显式代理 + 鉴权。

### 8.2 性能

- 流式：SSE 分块，首 token 尽快。
- 文件树：目录缓存 + 增量扫描（chokidar）。
- 大文件预览：只读头部/按需分片。

### 8.3 成本控制

- 每次对话显示 token 与估算费用（Pi SDK 已提供 usage）。
- 预算上限：超限时付费工具默认 Approve/Deny（策略联动）。
