# pi-agent 产品市场验证 - 用户角色与测试用例

## 一、核心用户角色定义

### 角色 1：企业开发者（Enterprise Developer）
- **背景**：中大型企业的技术团队成员，负责将 AI 能力集成到业务系统
- **核心需求**：
  - 快速创建和部署 AI Agent
  - 与现有业务系统 API 集成
  - 多团队协作与权限管理
  - 生产环境稳定性与监控
- **技术能力**：高（熟悉 API、SDK、Docker、K8s）
- **使用频率**：日常高频使用

### 角色 2：独立开发者/自由职业者（Freelancer）
- **背景**：个人开发者或小型工作室，承接 AI 相关项目
- **核心需求**：
  - 低门槛快速上手
  - 成本控制（Token 消耗、API 调用费用）
  - 快速交付客户解决方案
  - 模板和复用能力
- **技术能力**：中高
- **使用频率**：项目驱动，中频使用

### 角色 3：产品经理/业务分析师（PM/BA）
- **背景**：非技术背景的产品人员，需要验证 AI 产品想法
- **核心需求**：
  - 可视化配置界面
  - 无需代码创建 Agent
  - 快速原型验证
  - 数据分析和效果评估
- **技术能力**：低（需要无代码/低代码方案）
- **使用频率**：验证阶段中频使用

### 角色 4：运维/DevOps 工程师（DevOps Engineer）
- **背景**：负责 AI 系统的部署、监控和维护
- **核心需求**：
  - 一键部署能力
  - 实时监控和告警
  - 日志追踪和调试
  - 性能调优和成本优化
- **技术能力**：高（熟悉基础设施）
- **使用频率**：日常运维使用

### 角色 5：内容创作者/知识工作者（Content Creator）
- **背景**：需要 AI 辅助创作、知识管理的个人用户
- **核心需求**：
  - 简单易用的对话界面
  - 知识库管理（文档上传、检索）
  - 多 Agent 协作
  - 内容生成和编辑
- **技术能力**：中低
- **使用频率**：日常高频使用

## 二、核心使用场景与测试用例

| 知识库管理 | 企业开发者、内容创作者 | 4 | P0 |

### P0 级测试用例（核心功能）

#### TC-001：新用户注册与首次登录
- **角色**：全部
- **前置条件**：未注册用户
- **测试步骤**：
  1. 访问系统首页
  2. 点击注册按钮
  3. 填写用户名、邮箱、密码
  4. 提交注册
  5. 使用新账号登录
  6. 验证登录后跳转页面
- **预期结果**：注册成功，登录后进入 Dashboard
- **验证点**：注册流程耗时、表单验证提示、错误处理

#### TC-002：对话式 Agent 创建（自然语言描述）
- **角色**：产品经理、内容创作者
- **前置条件**：已登录用户
- **测试步骤**：
  1. 进入 Agent 管理页面
  2. 点击"创建 Agent"
  3. 选择"从描述创建"
  4. 输入描述："我需要一个客服 Agent，能回答产品使用问题，语气友好专业"
  5. 等待系统生成配置
  6. 预览生成的配置（提示词、模型、温度）
  7. 保存 Agent
  8. 验证 Agent 出现在列表
- **预期成功标准**：30 秒内生成配置，配置合理可用
- **验证点**：生成速度、配置质量、描述理解准确度

#### TC-003：模板快速创建 Agent
- **角色**：独立开发者、企业开发者
- **前置条件**：已登录用户
- **测试步骤**：
  1. 进入 Agent 创建页面
  2. 浏览可用模板（客服/写作/代码/数据分析/教学/通用）
  3. 选择"代码助手"模板
  4. 修改名称为"Python 代码助手"
  5. 调整温度参数为 0.3
  6. 保存并验证
- **预期结果**：基于模板快速创建成功
- **验证点**：模板数量、参数可调性、创建耗时

#### TC-004：知识库创建与文档上传
- **角色**：企业开发者、内容创作者
- **前置条件**：已登录用户
- **测试步骤**：
  1. 进入知识库页面
  2. 点击"新建知识库"
  3. 填写名称："产品文档库"
  4. 填写描述："存储产品相关文档"
  5. 选择嵌入模型
  6. 创建知识库
  7. 进入知识库详情
  8. 上传 PDF 文档（产品手册）
  9. 上传 Markdown 文档（API 文档）
  10. 等待文档处理完成
  11. 验证文档状态变为"已就绪"
- **预期结果**：文档上传成功，处理完成后可检索
- **验证点**：支持格式、处理速度、状态反馈

#### TC-005：知识库混合搜索
- **角色**：企业开发者、内容创作者
- **前置条件**：已上传文档的知识库
- **测试步骤**：
  1. 进入知识库详情
  2. 在搜索框输入"如何重置密码"
  3. 执行搜索
  4. 查看搜索结果（相关片段、来源文档、相似度分数）
  5. 切换搜索模式（向量/关键词/混合）
  6. 对比不同模式结果
- **预期结果**：返回相关文档片段，混合模式效果最优
- **验证点**：搜索速度、结果相关性、模式切换

#### TC-006：Agent 对话交互
- **角色**：全部
- **前置条件**：已创建的 Agent
- **测试步骤**：
  1. 进入 Agent 详情
  2. 点击"开始对话"
  3. 发送第一条消息："你好，你能做什么？"
  4. 等待回复
  5. 发送第二条消息："帮我写一段产品介绍"
  6. 验证回复质量
  7. 检查对话历史保存
  8. 验证 Token 消耗统计
- **预期结果**：流式回复，内容相关，历史保存
- **验证点**：响应速度、回复质量、流式输出、统计准确

#### TC-007：Agent 绑定知识库
- **角色**：企业开发者
- **前置条件**：已有 Agent 和知识库
- **测试步骤**：
  1. 进入 Agent 编辑页面
  2. 找到"知识库"配置项
  3. 绑定"产品文档库"
  4. 保存配置
  5. 开始对话
  6. 提问知识库相关问题："我们的 API 支持哪些认证方式？"
  7. 验证回答引用了知识库内容
- **预期结果**：Agent 利用知识库回答问题
- **验证点**：绑定流程、RAG 效果、引用准确性

### P1 级测试用例（重要功能）

#### TC-008：可视化工作流编排
- **角色**：企业开发者、产品经理
- **前置条件**：已登录用户
- **测试步骤**：
  1. 进入工作流页面
  2. 点击"创建工作流"
  3. 从拖拽面板添加节点（开始→Agent→结束）
  4. 配置 Agent 节点（选择已有 Agent）
  5. 连接节点
  6. 保存工作流
  7. 运行工作流
  8. 查看执行结果
- **预期结果**：可视化编排成功，工作流正常执行
- **验证点**：拖拽体验、节点类型、连线逻辑、执行反馈

#### TC-009：多 Agent 协作工作流
- **角色**：企业开发者
- **前置条件**：已创建 2+ Agent
- **测试步骤**：
  1. 创建工作流
  2. 添加"输入"节点
  3. 添加第一个 Agent（分析 Agent）
  4. 添加第二个 Agent（总结 Agent）
  5. 配置数据传递
  6. 运行工作流
  7. 验证 Agent 间数据流转
- **预期结果**：多 Agent 按序协作，数据正确传递
- **验证点**：数据传递、执行顺序、错误处理

#### TC-010：调试面板使用
- **角色**：企业开发者、DevOps
- **前置条件**：正在执行的对话或工作流
- **测试步骤**：
  1. 开始一个对话
  2. 打开调试面板
  3. 查看执行步骤（LLM 调用、工具调用）
  4. 查看 Token 消耗
  5. 设置断点
  6. 单步执行
  7. 查看变量状态
- **预期结果**：调试信息完整，断点功能正常
- **验证点**：信息粒度、断点响应、变量查看

#### TC-011：执行监控面板
- **角色**：DevOps、企业开发者
- **前置条件**：系统有执行记录
- **测试步骤**：
  1. 进入执行监控页面
  2. 查看总览 KPI（总执行数、Token、成本、耗时）
  3. 查看成本趋势图
  4. 查看模型占比饼图
  5. 过滤执行状态（成功/失败/运行中）
  6. 切换时间范围（1天/7天/30天）
  7. 点击执行记录查看详情
- **预期结果**：数据准确，图表清晰，过滤正常
- **验证点**：数据实时性、图表交互、过滤准确性

#### TC-012：多租户与团队管理
- **角色**：企业开发者、DevOps
- **前置条件**：已登录企业管理员账号
- **测试步骤**：
  1. 进入团队管理页面
  2. 创建新团队
  3. 邀请成员（邮箱邀请）
  4. 设置成员权限（管理员/编辑/查看）
  5. 验证权限控制生效
  6. 切换团队上下文
- **预期结果**：团队创建成功，权限控制准确
- **验证点**：邀请流程、权限粒度、切换体验

#### TC-013：Docker 一键部署
- **角色**：DevOps
- **前置条件**：已安装 Docker 和 Docker Compose
- **测试步骤**：
  1. 下载 docker-compose.prod.yml
  2. 配置环境变量（JWT_SECRET、DB 连接等）
  3. 执行 `docker-compose up -d`
  4. 验证服务启动（Web、API、DB）
  5. 访问 Web 界面
  6. 执行健康检查
  7. 查看日志
- **预期结果**：一键部署成功，服务正常运行
- **验证点**：部署文档完整性、启动速度、健康检查

#### TC-014：Webhook 与 API 集成
- **角色**：企业开发者
- **前置条件**：已部署的系统
- **测试步骤**：
  1. 获取 API 文档
  2. 创建 API Key
  3. 调用 Agent 创建 API
  4. 调用对话 API
  5. 验证认证机制
  6. 测试速率限制
- **预期结果**：API 调用成功，认证有效
- **验证点**：文档质量、认证方式、错误响应

### P2 级测试用例（增强功能）

#### TC-015：产物管理与下载
- **角色**：企业开发者、独立开发者
- **前置条件**：已执行的对话或工作流
- **测试步骤**：
  1. 进入产物管理页面
  2. 查看历史产物列表
  3. 按类型过滤（文档/代码/图片）
  4. 下载产物
  5. 删除产物
  6. 验证存储空间统计
- **预期结果**：产物列表完整，下载正常
- **验证点**：列表加载速度、下载完整性、存储统计

#### TC-016：Agent 版本管理
- **角色**：企业开发者
- **前置条件**：已有 Agent
- **测试步骤**：
  1. 编辑 Agent 配置
  2. 保存为新版本
  3. 查看版本历史
  4. 回滚到旧版本
  5. 对比版本差异
- **预期结果**：版本管理功能正常
- **验证点**：版本创建、回滚、差异对比

#### TC-017：批量操作
- **角色**：企业开发者、DevOps
- **前置条件**：多个 Agent/知识库
- **测试步骤**：
  1. 选择多个 Agent
  2. 执行批量删除
  3. 执行批量导出
  4. 验证操作确认机制
- **预期结果**：批量操作成功，有确认提示
- **验证点**：选择交互、确认机制、操作反馈

#### TC-018：通知与告警
- **角色**：DevOps
- **前置条件**：已配置通知渠道
- **测试步骤**：
  1. 配置邮件通知
  2. 设置告警规则（成本超阈值、执行失败率）
  3. 触发告警条件
  4. 验证通知发送
  5. 查看告警历史
- **预期结果**：告警触发准确，通知及时
- **验证点**：配置灵活性、触发准确性、通知时效

## 三、测试执行计划

### 执行顺序
1. **第一轮**：P0 用例（TC-001 ~ TC-007）— 核心功能验证
2. **第二轮**：P1 用例（TC-008 ~ TC-014）— 重要功能验证
3. **第三轮**：P2 用例（TC-015 ~ TC-018）— 增强功能验证

### 数据记录项
- 用例 ID
- 执行角色
- 开始时间
- 完成时间
- 步骤完成率
- 异常/错误记录
- 用户主观评分（1-5）
- 改进建议

### 通过标准
- P0 用例通过率 ≥ 95%
- P1 用例通过率 ≥ 85%
- P2 用例通过率 ≥ 70%
- 无阻塞性（Blocker）缺陷
- 无严重（Critical）缺陷 ≥ 2 个
