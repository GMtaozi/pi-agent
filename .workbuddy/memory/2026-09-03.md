## 子代理 429 的真相（已查证，推翻此前判断）

**结论：429 与用户的 LongCat Key 无关，是子代理回退到平台内置模型 `hy3` 触发的平台配额限制。**

证据链（日志：`~/.workbuddy/logs/2026-09-03/pi-agent__4bc6570e5f3cdbf491ad3cadd4cade1b.log`）：

| 项 | 主会话 | 子代理 |
|---|---|---|
| 模型解析 | 用户在 UI 选的 LongCat-2.0（`custom-local`） | `general-purpose` 无显式 model → `auto` → `first-available='hy3'` |
| 请求端点 | `api.longcat.chat/openai/chat/completions` | `copilot.tencent.com/v2/chat/completions` |
| 用谁的 Key | 用户自己的 `ak_2Fc…GM0D` | 平台 Key |
| 请求次数 | 1892 | 1360 |
| 429 次数 | **0** | **39**（8 个唯一 requestId 全部命中 copilot） |

关键日志行：
```
[AgentManager.getModel] agent='general-purpose' has no explicit model (auto); resolved to first-available='hy3'
[ModelProvider] Sending request: agent=general-purpose, model=hy3, requestId=39819f0b..., url=https://copilot.tencent.com/v2/chat/completions
```
- models.json 只配了 1 个模型 LongCat-2.0（vendor=Custom，url=api.longcat.chat）
- 429 重置时间是**滚动窗口**（09:35 提示 14:13 重置，21:56 提示次日 15:22 重置），非固定每日重置
- 8/8 个 429 requestId 反查端点全部为 copilot.tencent.com，无例外

**此前判断的错误**：我曾说"并发过多"和"今日 API 总配额耗尽"——均不成立。用户说"我 longcat 用的好好的"是对的，LongCat 一次 429 都没有。

**应对**：减少并发无效；等 hy3 窗口重置无效（主会话不受影响）。真正解法是让子代理继承主会话模型，或等平台 hy3 配额恢复。

## 重要经验：子代理 429 频率限制（旧判断，已被上文推翻，保留以记录排查过程）
- 现象：召唤 teammate 返回 429，主 agent 对话正常
- 诊断：单次召唤 1 个子代理仍 429 → 不是并发过多，是**今日 API 总配额耗尽**
- 重置时间：次日同一时段（本次为 2026-09-04 15:22 UTC+8）
- 应对：减少并发无效，只能等待重置或切换模型；被中断的子代理**产物可能已落盘**，应先检查文件系统再判定任务失败
